# 安装、启动器与发布检查点

按本次操作选择小节。实际安装/回滚和工坊 API 命令见[发布流程](release-workflows.md)；本页不扩大既有授权范围，不要求重复确认已经授权的操作。

## 本地安装与启动

- 构建完成不等于已安装。核对同步收据与实际文件哈希、启用包身份和对应启动日志；旧游戏进程需重启加载新资源。本地/工坊同身份副本只启用一份。
- `content_load.json` 可能由启动器数据库重建。用适配当前应用/数据库的安装启用流程协调两者，并核对官方启动器重启后的保持和撤回；不把手改 JSON 当持久启用证明。
- 启动器版本与数据库迁移记录须成对审核。发现旧入口读不了已升级数据库时，先检查官方引导器和实际选用版本，不删除数据库或迁移记录，不靠降级抹平错误。当前 CLI 不支持的应用/迁移须先核验，见[启动器运行时](launcher-runtime-workflows.md)。
- Steam 版需要游戏/DLC 上下文时优先经 `Steam.exe -applaunch <AppID>` 和已配置官方入口启动；裸跑引导器曾缺少 App ID。机器上的确切路径、启动选项和修复方案留在本机项目约定，复核后再用。
- 如任务需要界面操作，区分 Steam 主窗、属性弹窗和启动器；隐藏重复控件或遮挡截图不能作成功证据。操作后读回持久设置。遵守用户是否允许界面验证的安排。
- 启动器封面与 ACP 预览路径一起检查。已核对的 2026.13 使用 `.metadata/thumbnail.png`，同名 JPG 不被读取；其他版本重新核对。文件被打包不证明实际条目显示正常。

## 工坊更新

- 沿已有条目 ID 更新；历史发布权限不自动扩展到新的提交或可见性变化。上传结果未知时先 reconcile/核对远端，不能盲目重传或另建条目。
- 主预览图保持小于 1 MB；遇到 `EResultLimitExceeded`（25）先查图片体积与云空间。此前已创建条目就沿原 ID 恢复，不以重复创建解决配额错误。
- 上传成功、下载内容匹配与玩法可用分别报告；不能把传输验证当作原生合并或实机验收。法律协议由用户本人处理。

## 证据与清理

- 有效计划、安装/回滚收据和冻结证据绑定路径、输入哈希与当时状态。不要随意搬动或修改内容以匹配新状态；将可变维护说明用于历史证据前先保存独立快照。
- 清理可重建缓存与已获授权的过期材料，保留当前源、必要运行依赖和仍有效的收据。被移除输入对应的报告仅作历史记录，不声称仍可完整重放。
- 临时存档的最小取证和精确删除见[运行时排错](runtime-diagnosis-workflows.md)；不默认长期保留整份存档、启动器安装包或多套测试树。
