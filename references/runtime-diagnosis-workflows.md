# 运行时排错与用户复测

定位已加载 Mod 的实际执行断点；这不是新的通用存档解析或原生接口能力。复制条件/资源前的类型、枚举、宿主核对统一见[资源检查点](authoring-checks.md)，安装版本核对见[安装检查点](deployment-checks.md)。

## 一轮有判据的诊断

- 绑定同一轮的维护源、安装哈希、启动日志和施法前/后存档；旧进程、同名旧存档和旧阶段值不能冒充本轮证据。
- 按“宿主合法→目标选中→效果执行→事件到达→条件通过→生成请求→实体存在→后续交互”找第一个断点。随机结果难判时，在暂存候选固定一个明确结果，保留位置条件，记录阶段、选中资源和一次性标记。
- 复测前说明新增证据、修复的阻塞和成功/失败判据。通常一次受控操作及单独后存档即可；需要多次才增加次数。失败后看阶段是否前进，不反复只调概率、延时或扩大目标范围。

## 按现象区分证据

| 现象/证据 | 核对重点 | 不能直接得出的结论 |
| --- | --- | --- |
| 回调、注册、“已应用”或退出码成功 | 完整对象、引用及实际合并结果 | 法术有效或玩法正常 |
| 资源往返/宿主校验通过 | 对应加载上下文、getter/签名和最终入口 | 选择器会命中、时序正确；克隆宿主/ACP镜像不等于最终合并 |
| 目标有标记，事件计数未变 | 效果与事件派发之间的路径 | 奖励概率太低 |
| 事件到达但条件阶段未前进 | 函数、参数包装、引用和本次状态 | 改个名称或结果 ID 就能修好 |
| 固定结果模式出现另一种奖励 | 实际资源身份、原版/其他Mod分支及既有地图对象 | 私有流程已成功 |
| 已请求生成或处理结束 | 实际新增实体和合法放置条件 | 放置必然成功 |
| 部队暂时不可见 | 前后实体 ID、资源、所属方和坐标 | 单位已删除；总数不变也可能掩盖一增一减 |

保留原版事件时，按设计在明确的本包条件下避免双重奖励，同时保留普通原版事件；不全局禁用原版逻辑。旧档是否实例化新增监听器需要实例证据；复用旧入口有效，不等于证明“旧档不注册新监听器”。

## 时序、视野与结果范围

- 分开检查目标收集与效果应用；数组排列不代表最终执行顺序，延时还需确认单位和类型。涉及临时不可通行地形时，地形处理完成后再召唤，并检查落点和既有部队。
- 探索刷新明确受益玩家与区域，避免意外为所有玩家开图。“地图已探索”与“奇观探索完成/已占领”不同；生成模型不足以证明事件、战斗或收益可用。
- 多项修改共同通过只确认该组合有效；没有单项对照，不把一个延时/刷新独自写成原因。后存档也不能还原过去每一帧的显示状态。
- 固定结果通过后，核对正常模式的实际差异，切换后读回已安装说明。共享流程通过不等于随机池逐项通过；标记已保存不等于读档后再次施法防重复通过。遵守用户的实测安排，保留未覆盖项。

## 最小取证与清理

- 保留日志路径/哈希，输出去重类别、次数和少量样例；查询限制到相关对象/字段，不倾倒完整树、底层文件缓冲区或重复警告。日志通道未启用时，没有输出不能单独证明没执行。
- 只保留所需存档片段、实体身份和输入哈希；不默认复制整份用户存档。仅在已有授权范围内清理具体测试档，核对名称、路径、时间和内容，不凭“最新文件”批量删除。
- 通过云存储接口删除时核对账户、应用及远端内容哈希，之后确认目标消失、其他存档未变。报告注明已删完整输入不可重放；其他证据保留规则见[安装发布检查点](deployment-checks.md)。
