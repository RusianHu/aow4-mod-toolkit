# 验证方法与证据边界

公开仓库提供源码、合成测试和可重现命令。原始机器调试记录、游戏文件、私有Mod、启动器数据库、账户/上传收据和完整原生运行目录不随源码分发；需要它们的验证由执行者在自己的私有工作区生成。

## 源码与分发

```powershell
python -m unittest discover -s tests -p 'test_*.py'
python scripts/package_skill.py --output "<仓库外的新目录>"
```

使用全部依赖extras运行完整合成回归。CI使用GitHub托管Windows/Python环境，不携带游戏。打包从干净提交生成ZIP、SHA-256和逐文件清单，要求双语README、MIT许可证及第三方声明，并拒绝凭据文件、官方/游戏二进制及本机报告目录。

独立运行时应在仓库外解压，以Python `-I`调用导出入口，移除PYTHONPATH/PYTHONHOME依赖，并比较运行时文件指纹。公开的[GitHub Actions](https://github.com/RusianHu/aow4-mod-toolkit/actions)给出对应提交的合成/打包结果；不能将其他提交的通过记录移用于新代码。

## 原生与内容验证

| 验证 | 可证明的范围 | 不能据此推定 |
| --- | --- | --- |
| 静态解析/索引/schema | 对应文件与已识别格式/字段；保留未解析项 | 完整语义、最终加载顺序 |
| 构造/标量/收入编辑 | 请求值、未选字段与独立进程读回 | 任意类或任意复杂属性可编辑 |
| RPK往返 | ID/类型/字段/顺序及不透明数据比较 | 游戏激活、渲染或玩法 |
| ACP准备/合并 | 显式输入和顺序上的预期数据保留 | 全局播放集优先级、存档/多人 |
| 启动器 | 匹配应用/schema/迁移下的指定操作 | 其他版本、官方重启保持或实际挂载 |
| 工坊传输 | 身份、元数据和下载内容核对 | 内容合法、可玩或兼容 |

原生证据须绑定游戏/工具哈希、后端指纹、输入和上下文，并用独立读回验证。回调、零退出码、已应用标记或零诊断不能单独证明成功。失败、不匹配、原生诊断及未评估项继续保留；公开文档只提炼脱敏方法，不据此抹去执行者的原始失败证据。

游戏更新后按[版本流程](../references/game-version-workflows.md)重新检查所需范围。当前配置身份见[兼容性矩阵](MANTA_COMPATIBILITY.md)。
