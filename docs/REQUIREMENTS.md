# 开发需求与完成标准

本文件定义最终目标；开发顺序见 [ROADMAP.md](ROADMAP.md)，当前事实见 [STATUS.md](STATUS.md)。三份文件随本 Skill 的独立 Git 仓库维护。它们用于开发本工具，普通 Mod 操作不必加载。

## 产品目标

让自动化 Agent 通过项目级 Skill 和 CLI，完成 AoW4 Mod 的创建、内容编辑、版本维护、检查、构建、安装启用和 Steam 创意工坊发布。优先覆盖 Mod 作者常用操作，并逐步达到接近官方编辑器的开发维护广度。

日常工作应以低上下文开销的命令、分页查询和结构化结果为主。尚未覆盖的操作可使用明确说明限制的官方编辑器桥接；桥接不能算作已有纯 CLI 能力。

## 需求与验收

| 编号 | 最终能力 | 验收要求 |
| --- | --- | --- |
| R01 | Agent 入口 | Skill 可被项目发现，独立检出可运行；命令可导航，输出可供自动化处理，不依赖父项目目录结构。 |
| R02 | 现有 Mod 维护 | 能检查原版更新影响、引用和依赖、冲突，保留作者修改进行迁移，并构建修复包；支持有选择地恢复原版字段而不重建资源身份、覆盖其他作者修改；用有代表性的实际 Mod 验证完整维护流程。 |
| R03 | 常见玩法 Mod 创作 | 能从空项目创建常用资源、配置属性和引用、接入游戏入口、添加本地化与图标；提供法术/研究、单位/装备、建筑等代表性完整流程，而非只有空对象构造。 |
| R04 | 素材制作 | 覆盖图像与纹理、静态模型与材质、骨骼/动画、常用特效及其游戏入口；各类明确支持格式、依赖和领域约束，结果可由官方后端独立读回。 |
| R05 | 地图制作 | 支持地图创建或模板派生、地形、实体与部署区编辑、身份分配和合法位置、保存与读回；不能只覆盖少量固定实体的局部修改。 |
| R06 | 校验和构建 | 构建正确运行包，保留来源及未完成事项；原生校验覆盖对应内容，失败、未评估、诊断和已通过须区分，发布快照可离线复核。 |
| R07 | 安装与启用 | 完成本地安装、登记、启用和排序；官方启动器重启后保持状态；提供备份及回滚，并验证本机实际启动器与数据库配对。 |
| R08 | 工坊发布维护 | 支持首次发布、已有条目更新、未知结果恢复、元数据及下载内容核对；用获得对应授权的实际操作验证发布链路。 |
| R09 | 可维护的独立工具 | 源码、测试、需求、开发路线及当前状态在 Skill 仓库内；依赖清楚，版本变化可追踪；另一 Agent 能据文档继续工作。 |
| R10 | 作者视角的内容调查 | 从中文/其他已索引语言、文本键、内部名、ID 和 DataStoreTag 定位原版或 Mod 内容；沿当前入口追踪研究、解锁、目标器、效果和费用，保留共享影响、重复引用、歧义、版本与未解析项；调查结果可直接指导后续暂存修改。 |

R10 不以“包内存在同名资源”代替当前入口可达，也不以文本或构造默认值代替已加载效果值。基础检索与引用导航、常见内容解释、嵌套原生读取和完整语义快照分阶段验收；不能把第一阶段视为全部完成。

## 作者工作流的完成尺度

- 一件作品由临时 Python 脚本完成，证明该作品的对应结果，不证明 Skill 已提供可复用流程。重复使用的字段查找、复制/恢复、差异审查和暂存应进入正式 CLI；配方只描述作品意图和选择，不复制二进制写入器。
- 批量恢复必须显式绑定每个目标与原版/模板资源，保留资源 ID、入口和未选字段；原版省略字段须区分“删除覆盖”与“写入零/false”，不得猜测运行时默认。失败时不留下半份新输出。
- 原生保存造成的字段顺序变化与实际值、类型、数组顺序、引用变化分开报告。未知或歧义编码保持原始字节比较；结构相等不能升级为玩法语义相等，也不能自动清除既有发布门槛。
- 正式作者操作应能从明确文件直接读取和规划，不要求为了查看新暂存资源先重建整份游戏索引；引用影响与跨包依赖调查仍需相应索引/上下文。
- 开局加成须区分指定研究、帝国发展、被动效果与标签/随机筛选；列表声明、目标身份及最终授予分别验收。提示须按实际入口检查自定义文本键与原生生成路径，空键、模板继承或静态链接不证明二级提示已呈现。
- 游戏更新后分别核验静态格式、提取器、语义规则、原生ABI和启动器应用/数据库配对。旧版本通过的能力须标明当前是否可用；不能只更新哈希而沿用未核验偏移，也不能把一次性作品探针升级为通用支持。
- 环境诊断须区分“文件存在”“当前版本已审核”“操作已通过”。原生构建中同一ABI缺失导致的批量失败应明确根因；检查进程退出0、静态门槛通过或显式未请求原生检查，都不能表示完整原生验证通过。
- 开局选择配方须核对标签身份、保留原版TagSet、选择器唯一目标、声明的互斥组及双向限制，并绑定实际覆盖环境。作者脚本的成功仅为正式CLI的验收用例，未接入通用流程前保持能力缺口。

## 不可省略的边界

- 原版和生产 Mod 不作为开发测试输出；使用新暂存目录及独立测试项目。
- 实际玩法验收按具体作品和当前任务约定决定；已有作品的免测约定不能推广为所有 Mod 永久免测。历史静态分析、官方原生读回和工具行为证据不得表述为玩法、存档或多人通过。
- 原生回调成功、状态标志、零诊断或较多测试不能单独证明完整能力。每项完成须对应其实际验收范围。
- 新的工坊提交或可见性变更须有对应发布授权。历史测试授权不自动延续。
- 不使用子代理；不处理 CE 表或游戏内存作弊。

## 总体完成条件

上述需求均有可执行、可复核的用户流程和验收证据，主要常用内容类别不再依赖未完成的研究原型，且关键剩余限制已向用户说明。局部功能或若干接口通过不能代替总体完成；范围调整须来自用户，不能为了宣布完成而缩小目标。
