# 开发路线与进度控制

范围以[需求](REQUIREMENTS.md)为准；当前能力见[状态](STATUS.md)。公开资料保留可复用方法，不维护本机调试流水。

| 优先级 | 用户结果 | 完成条件 |
| --- | --- | --- |
| P0 | 随游戏更新维持资源开发/维护 | 分别审核静态格式、schema/语义、原生ABI与启动器配对；保留准备改写、默认省略及诊断门槛 |
| P1 | 从调查结果实施精确修改 | 显式目标/字段、身份与未选数据保留、陈旧输入拒绝、独立读回和原子暂存 |
| P1 | 解释实际效果与共享影响 | 扩展条件/列表/引用编码；区分声明、已加载值、最终覆盖与未解析项 |
| P2 | 完整常用内容创作 | 连接身份、研究/解锁、目标器/效果、费用、AI、素材及文本；用对应作者任务验收 |
| P2 | 开局选择及提示 | 审核标签唯一性、双向互斥、最终合并上下文与实际多层提示 |
| 后续 | 素材、动画与地图广度 | 逐项适配版本，覆盖空间/骨架/动画、材质/特效及完整地图入口，不扩大历史受限结论 |
| 最终 | 全范围交付审计 | 逐项对照R01–R10及对应证据；未满足前不宣告总体完成 |

工作方式：先定义用户结果与验收范围，优先现有CLI；遇到缺口再补工具。按风险保留负例、失败和未评估项，不以放宽比较获得通过。源码/文档同步维护，原始机器证据留在分发目录外的私有工作区。
